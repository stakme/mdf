# Docs Overview

> 🚧 mdf 0.x is experimental and may change, or even be discontinued, over time.

`mdf` is a small, general‑purpose CLI for developers who keep knowledge in
Markdown. It treats front matter as first‑class data so you can organize,
filter, validate, and publish notes without standing up servers or bespoke
backends. Coding agents (like Codex) can query your workspace directly from the
filesystem: no MCP bridge or API endpoints required.

## Why Markdown + front matter

In a fast‑moving AI era, tools come and go; plain text endures. Markdown files
with simple front matter remain readable, portable, and diff‑friendly. Rather
than inventing new silos for each agent, `mdf` offers a common, durable language
that agents and humans can both work with.

## Core capabilities

- Front‑matter filtering: target documents by fields, not just text (e.g.,
  `status=todo and owner=me`).
- CLI‑first workflows: create, list, validate, update, and export with
  predictable schemas.
- Agent‑friendly access: everything lives on disk; automation can read it safely
  without services.
- Lightweight viewer: `mdf viewer` launches a simple web UI for team review and
  prioritization during screen shares.

## Everyday examples

- Backlog triage with an alias:
  - In `.config/mdf.mts`, define `todo: list --filter "status=todo" ./TODO`.
  - Run `mdf run todo` to list unfinished tickets by front matter.
- Docs export: run `mdf export ./docs` to generate a static site filtered the
  way you want.

## How the documentation is organized

- Getting Started: installation, configuration, and the core authoring workflow.
- Commands: focused pages under `commands/` with examples and recommended flags.
- Automation Guides: exporting a docs site and wiring it into CI (includes a
  GitHub Pages workflow).
- Recipes: common day‑to‑day tasks like grooming TODO queues or preparing
  release notes.
