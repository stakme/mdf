`mdf` is a small, general‑purpose CLI for developers who keep knowledge in
Markdown files stored in git.

**🚧 mdf 0.x is experimental and may change, or even be discontinued, over
time.**

## What it does

This CLI is an experimental attempt to use Markdown + front matter to manage
knowledge in a way that is accessible to both humans and AI agents.

### Front matter

Front matter is a YAML block at the top of the file, separated from the body by
a blank line. It is used to store metadata about the document.

```mdx
---
title: Let's build a CLI to manage knowledge in Markdown files stored in git
status: todo
author: "@stakme"
updated_at: 2025-10-12T00:09:21.406Z
---

# Introduce code highlighting like GitHub
```

### Schema and validation

You can define schema per directory in the config file. This feature helps you
organize, filter, validate, and publish notes without standing up servers or
bespoke backends.

```ts
docs: defineSchema({
  glob: "docs/**",
  schema: z.object({
    title: z.string().min(1).default("title"),
    description: z.string().optional(),
    tags: z.array(z.string()).default(() => []),
    draft: z.boolean().default(true),
    chapter: z.number().default(0),
    updated_at: z.date().default(() => new Date()),
  }),
  sort: (a, b) => a.chapter - b.chapter,
  visibleFields: ["tags"],
}),
```

### CLI workflows

`mdf` offers a CLI to create, list, validate, update, and export notes. Coding
agents (like Codex) can query your workspace directly from the filesystem: no
MCP bridge or API endpoints required.

```sh
# Create a new file with front matter.
# You also can use template to fill the body.
$ npx @stakme/mdf new --fm 'title=something new' ./docs
docs/01K7AW2SKXMNENW0CQ6BR4XG5B.md

# List files with specified front matter.
$ npx @stakme/mdf list --filter "draft=true" ./docs    
./docs
└── something new (./docs/01K7AW2SKXMNENW0CQ6BR4XG5B.md)

# Update existing file with front matter.
$ npx @stakme/mdf update --fm draft=false --fm updated_at docs/01K7AW2SKXMNENW0CQ6BR4XG5B.md
Updated ./docs/01K7AW2SKXMNENW0CQ6BR4XG5B.md
```

### Viewer and export

`mdf` offers a simple viewer to preview your notes in a web UI. And it exports
static HTML files: what you see here is generated by the export command.

```sh
$ npx @stakme/mdf viewer ./docs
```

## Why Markdown + front matter

In a fast‑moving AI era, tools come and go; plain text endures. Markdown files
with simple front matter remain readable, portable, and diff‑friendly. Rather
than inventing new silos for each agent, `mdf` offers a common, durable language
that agents and humans can both work with.

## Core capabilities

- Front‑matter filtering: target documents by fields, not just text (e.g.,
  `status=todo and owner=me`).
- CLI‑first workflows: create, list, validate, update, and export with
  predictable schemas.
- Agent‑friendly access: everything lives on disk; automation can read it safely
  without services.
- Lightweight viewer: `mdf viewer` launches a simple web UI for team review and
  prioritization during screen shares.

## Everyday examples

- Backlog triage with an alias:
  - In `.config/mdf.mts`, define `todo: list --filter "status=todo" ./TODO`.
  - Run `mdf run todo` to list unfinished tickets by front matter.
- Docs export: run `mdf export ./docs` to generate a static site filtered the
  way you want.
