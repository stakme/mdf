# Refactor config around vpath/vslug

## What I need

I want to make it easy to understand how virtual paths and slugs are computed
from schema data.

## So I will create...

## .config/mdf.mts

- Remove deprecated `virtualPath` and `virtualSlug` options.
- Prevent `new` command to add vpath/vslug properties to front matter: they
  should be virtual properties.
- Enhance arguments to lambda functions.

```ts
// Before
vpath: ((fm) => `/docs/${fm.title}`);

// After
// fm: Front matter data
// filename: Name of the file
// relativePath: Relative path of the file in specified context. For example, it will be `./100-overview.md` if I run `viewer ./docs` in this project with `100-overview.md` in `./docs` directory.
vpath: (({ fm, filename, relativePath }) => `/docs/${fm.title}`);
```

### list,viewer,export commands

- Use this lambda functions to compute virtual paths and slugs.
- If `vpath` is not defined, use its relative directory as virtual path. For
  example, if I run `viewer ./docs` in this project with `100-overview.md` in
  `./docs` directory, its virtual path will be `/`.
- If `vslug` is not defined, use its relative path as virtual slug. For example,
  if I run `viewer ./docs` in this project with `100-overview.md` in `./docs`
  directory, its virtual slug will be `100-overview`.
