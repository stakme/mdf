Let’s spin up a clean, fast “Markdown → pages” server in your **stakme/markdfm** repo using **Astro + React islands + Tailwind + shadcn/ui**. Below is a production-minded playbook you can follow end-to-end. No fluff—just signal. (And a smidge of meme-grade pep: “ship it like it’s Friday, but with Monday energy.”)

# Goals (TL;DR)

* Serve local Markdown/MDX as pretty, searchable pages.
* Keep URIs stable; frontmatter drives metadata.
* Minimal runtime JS (Astro FTW), React islands where it counts (nav/search).
* Developer-friendly: one command to dev, one to deploy.

# 4) Content Collections (read from `/docs`)

Define a collection that **globs** Markdown from the repo root `docs/` folder. This matches the “load from outside `src`” trick you used for backlogs: you pointed the base URL to a folder outside the app. 

**`site/src/content.config.ts`**

```ts
import { defineCollection } from "astro:content";
import { glob } from "astro/loaders";
import { z } from "astro/zod";

// We scan the repo root /docs directory.
// NOTE: the new URL trick resolves a path outside src/ cleanly.
export const collections = {
  pages: defineCollection({
    loader: glob({
      base: new URL("../../docs", import.meta.url).pathname,
      pattern: "**/*.{md,mdx}",
    }),
    schema: z.object({
      title: z.string().min(1),
      description: z.string().optional(),
      date: z.string().optional(),   // ISO string or yyyy-mm-dd
      tags: z.array(z.string()).optional(),
      draft: z.boolean().optional().default(false),
    }),
  }),
};
```

# 7) shadcn/ui in Astro (React island)

We’ll vendor the bits we need (Command/Popover/Dialog/Toggle) into `site/src/components/ui/*` and wire them via **client:only** React islands.

**Search.tsx** (using `Command` pattern à la shadcn)

```tsx
import * as React from "react";
import { Command, CommandInput, CommandList, CommandItem, CommandEmpty } from "./ui/command";
import { useState, useMemo } from "react";

type Item = { title: string; path: string; description?: string; tags?: string[] };
export default function Search({ items }: { items: Item[] }) {
  const [q, setQ] = useState("");
  const filtered = useMemo(() => {
    const s = q.trim().toLowerCase();
    if (!s) return items.slice(0, 50);
    return items.filter(i =>
      i.title.toLowerCase().includes(s) ||
      (i.description ?? "").toLowerCase().includes(s) ||
      (i.tags ?? []).some(t => t.toLowerCase().includes(s)),
    ).slice(0, 50);
  }, [q, items]);

  return (
    <div className="w-80">
      <Command>
        <CommandInput placeholder="Search docs…" value={q} onValueChange={setQ} />
        <CommandList>
          <CommandEmpty>No results</CommandEmpty>
          {filtered.map((it) => (
            <CommandItem key={it.path} onSelect={() => (location.href = it.path)}>
              <div className="flex flex-col">
                <span className="font-medium">{it.title}</span>
                {it.description && <span className="text-xs opacity-70">{it.description}</span>}
              </div>
            </CommandItem>
          ))}
        </CommandList>
      </Command>
    </div>
  );
}
```

**ThemeToggle.tsx** (cute, simple)

```tsx
import * as React from "react";
export default function ThemeToggle() {
  const [dark, setDark] = React.useState(
    typeof document !== "undefined" && document.documentElement.classList.contains("dark")
  );
  React.useEffect(() => {
    document.documentElement.classList.toggle("dark", dark);
  }, [dark]);
  return (
    <button className="text-sm px-2 py-1 rounded border" onClick={() => setDark(!dark)}>
      {dark ? "🌙 Dark" : "🌞 Light"}
    </button>
  );
}
```

> Why islands? Astro keeps your pages mostly static (zero-JS) and hydrates only these widgets. That’s performance on steroids—no “single-page-app tax.”

# 12) Nice-to-haves (a.k.a. chef’s specials)

* **Full-text search**: start with the in-memory filter above; graduate to **FlexSearch** in a client island or prebuild a static index JSON at build time (write a tiny `vite` plugin to collect docs and emit `/search-index.json`).
* **Breadcrumbs**: derive from file path segments.
* **Tags & filters**: read `tags: []` from frontmatter, add a sidebar.
* **Versioned docs**: include `version:` in frontmatter and filter on route param like `/v/:semver/...` (or separate collections).
* **Draft gating**: skip `draft: true` entries at build; show them under a preview flag locally.
* **Redirects**: keep a `redirects.json` and a catch-all route.

* **Images**: prefer local `public/` assets; for remote, add width/height to avoid CLS.
* **Accessibility**: headings in order; focus states retained (Tailwind default OK).
